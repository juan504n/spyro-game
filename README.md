# Gloaming Vale — a PS1-style Spyro DLC realm in three.js

*Lantern Keepers Pack · four realms, a homeworld and the portals between them · 700 + 700 + 650 + 800 + 550 gems · 5 beacons in each realm · a foundry for making more · no asset files — it is all code.*

A fan-made, unofficial tribute to the PlayStation-era Spyro games. It is a complete, playable platformer level
built with [three.js](https://threejs.org/) and rendered through a custom pipeline that reproduces the look of the
original console: 320×240 output, wobbling vertices, affine-warped textures, 15-bit colour with the PS1 dither
matrix, per-vertex lighting and fog, and 30 fps if you want it.

**Two looks.** The default is *smooth*, like an emulator's enhanced mode: 480 lines, smoothly filtered textures, 4× MSAA,
no dither and no vertex wobble. **Options → Graphics → LOOK → PS1 AUTHENTIC** switches to the strict 240p artefacts described below
(point-sampled textures, 15-bit dither, wobbling vertices, affine texture warp); every ingredient can also be toggled on its own.
**Options → Graphics → COLORS** is a separate grade: *classic* is the moody dusk palette, *vivid* (default) lifts the mid-tones and enriches
the colours, *extra vivid* goes further towards the bright, saturated look of console footage. It is applied to the 3D scene only (the HUD keeps its colours).

Everything you see and hear — terrain, 95 textures, sprites, the bitmap font, every model, the music and the
sound effects — is **generated by code at start-up**. The game loads no image, model or audio files.

## Play it

* **Instantly:** open [`docs/index.html`](docs/index.html) in a desktop browser (it is one self-contained file;
  also works from GitHub Pages if you serve `/docs`).
* **From source:**

  ```bash
  npm install
  npm run dev          # http://127.0.0.1:5173
  npm run build:single # rebuilds docs/index.html (single file, three.js inlined)
  ```

Needs WebGL2. Click the game once to capture the mouse and start the audio. On phones and tablets touch controls appear automatically (the display defaults to
widescreen there; **Options → Graphics → Display** switches back to the 4:3 frame). Held sideways the picture fills the screen; held upright it sits at the top of
the screen (below the platform's top inset, if it reports one: a notch, or an app's header drawn over the page), with the **MENU** button just under it and the black
below it left for your thumbs.

### Controls

| Action | Keyboard / mouse | Gamepad | Touch |
| --- | --- | --- | --- |
| Move | `WASD` / arrows | left stick / d-pad | left thumb (virtual stick) |
| Jump · glide (hold in the air) | `Space` | `A` / cross | JUMP |
| Breathe fire | `J` / `F` / left click | `X` / square | FIRE |
| Charge (ram) — hold | `K` / `Shift` / right click | `B` / circle | RAM |
| Ram jump — hold the ram, tap jump | `K` + `Space` | `B` + `A` | RAM + JUMP (two fingers) |
| Camera | mouse (after clicking) · `Q`/`E` | right stick · bumpers | right thumb drag |
| Re-centre camera behind Spyro | `R` | `Y` / triangle | CAM button (tap) |
| Camera mode: active → smart → passive | `C` | Pause → Camera | CAM button (hold) |
| Menu (pause, options, controls) | `Esc` / `P` | Start | **MENU** button (top centre) |
| Debug mode: off → compact → full | `F3` / `` ` `` | Pause → Debug mode | Menu → Debug mode |

**Ram jump.** As in the original you can jump while ramming: hold the ram button and tap jump, and he leaps with the charge kept, so he carries his full ram speed through the air
(a ram jump clears about 18 m, a plain running jump 8.7 m) and lands still ramming for as long as the ram button stays down; letting go of it ends the charge at once, in the air too.
(He can't glide while ramming.)

**On a phone** the game has a labelled **MENU** button, on the title screen and in play: centred under the picture when the phone is held upright (it covers none of the view), on the picture's top edge
when held sideways (below whatever the platform covers there: a notch, or an app that shows the page under its own header, `env(safe-area-inset-top)`). It opens the pause menu (resume, camera, debug mode,
options, travel, restart, quit: on a phone the controls page is a row of Options, so that the menu's six rows stay finger-sized); while a menu is open the button reads **RESUME** / **BACK**, and tapping outside the panel goes back too. The menu rows are finger-sized
(about 40 px each): Options is a short list of sub-pages (Camera & aim, Graphics → More graphics, Debug), and the thumb controls (move circle, JUMP, FIRE, RAM, CAM)
hide while a menu or a cutscene is showing.

**Camera modes** (also under **Options → Camera & aim**, saved with the other options), after the original games' *Active* / *Passive* setting:

* **Active** (default): the original's Active camera: it swings after Spyro quickly, on even a small lean of the stick, so he always runs into the view.
* **Smart**: a calmer Active. It ignores a thumb that wanders a little off straight, a strafe and a step back, and swings after him only when you push clearly
  forward-and-to-the-side, the harder the faster.
* **Passive**: the original's Passive camera: it follows Spyro's position but never turns by itself; you turn it (mouse, right stick, Q/E, right-thumb drag)
  or press `R` / tap CAM to swing it back behind him.

In every mode the camera stays put next to trees, lamp posts, fences and small rocks (it slides through them), climbs instead of zooming in when the ground rises behind
Spyro, and is only held back a little (never closer than about 60 % of its distance) by big things: houses, towers, gate pillars, boulders, or a cliff too steep to climb.

**Options → Camera & aim → Camera speed** scales every way of turning the camera by hand (x0.4 to x1.6). **Fire aim assist** (on by default) turns Spyro towards a
brazier, beacon, Snuffer, vase or chest that is up to about 65° off his nose while he breathes fire; the stick always has the last word. On a touch screen
the move stick's circle appears where the left thumb lands, has a small dead zone, and follows the thumb when it slides past the rim.

### Debug mode

Something looks wrong (a floating chest, a torn texture, an invisible wall)? Turn debug mode on and send a screenshot: the readout says where it is and what it is.
**`F3`** (or the backquote key) cycles off → compact → full; on a phone use **Menu → Debug mode** (also **Options → Debug**, which has *Show colliders* and *Text size*).
The setting is remembered. A crosshair marks the middle of the screen, and **on a touch screen you can tap the screen to pin the aim to that spot** (a ring marks it; tap the ring
again to let go): tap the thing that looks wrong and the `PIN` line gives its coordinates and what it is.

Coordinates are the level's own, in metres: **X = east, Z = south, Y = up** (Spyro faces south when his yaw is 0), the same numbers `src/game/level.js` and the layout scripts use.

| Line | What it says |
| --- | --- |
| `POS` | Spyro's X / Y / Z |
| `FACE`, `AREA` | compass heading, speed, what he is doing; the named place (Hearth Village, Windmill Hill, Sky Isle 2 ...) and the nearest road ribbon (`road east`, or how far from it in metres: a road ends in a flat edge, so past its end the distance is to that edge) or stream |
| `FLOOR` | the ground texture and the rule that chose it (`cliff (steep, slope > 0.74)`), the slope and the ground height — the rules are the ones the terrain mesh is built with; on a road it says so first (`cobble road main, over cobble (under a road)`), since a road is a ribbon drawn over the ground |
| `AIM` / `PIN` | where the crosshair (or the tapped spot) points: X / Y / Z and distance, and what is there (ground texture with its rule and grid cell, water, or a collider and the prop it belongs to; over flat ground, the nearest prop). Aim at the glitch itself, not only at Spyro: this is the point to fix |
| `PROP`, `OBJ`, `COLL` | the nearest props, gameplay things (chest, vase, Snuffer, beacon ...) and collision shape, each with its distance, clock direction (12h is straight ahead) and X / Z, and **`[layoutVillage]`**: the function in `src/game/levelgen` that placed it |
| full mode | game state (beacons, gems, checkpoint), camera, input, performance, view size and touch support, and the last errors |

The top line is the **build id** (a hash of `src/` and the build date; `node tools/build-id.mjs` prints the id of the source as it is now), so a screenshot also says which
version was running. *Show colliders* draws the collision shapes near Spyro as wireframes: green = solid, cyan = can be stood on, magenta = big enough to hold the camera
back, yellow = the nearest or the one the crosshair is on. The last errors and warnings the page logged are listed in full mode.

### Travel menu (to look at any part of the game)

**Travel** is a row of the title menu (`Esc`, or the **MENU** button on a phone) and of the pause menu. It lists the worlds (Gloaming Vale, Dawnhaven, Frostbloom Hollow, Emberfall Crags, Skyweaver Spires), then groups of places (the vale, the heights, sky and
summit; the country, lake and canyon, inside the crag, up and away; the goals, the country, the secrets), then the places: 85 of them in all (Mirrormere dock, Windmill Hill, the four sky isles, the observatory, the Great Beacon's room,
Dawnhaven's cove, the Echo Hall, the Frost Grotto, the crystal vault, the Forge, the summit, Frostbloom Hollow's Thaw Gate, its frozen lake, the glacier's heart chamber, the ice vault, the Hollow, Emberfall Crags' Cinder Flats, the stack in the lava, the Maw, the Furnace, the caldera, Skyweaver Spires' Skygate, the Lowfield, the Kite Isle, the Spindle Spires, the Loom ...). A place asks **ARE YOU SURE? YES / NO** (the cursor starts on NO; `Esc`, the BACK button or a tap outside the panel is NO too),
and YES takes the hero there:

* **in the world he is in** the screen blinks white and nothing is rebuilt: what he did there stays (gems, broken vases, lit lanterns);
* **in the other world** it is a trip like a portal's: this world is let go of (what was done in it is not kept: the prompt says so) and the other is built as the game generates it, fresh;
* **from the title menu** a place in the vale starts play there at once (no intro, with the line of controls PLAY would show); a place in Dawnhaven builds Dawnhaven.

He arrives on the floor the place names, facing the way it says, the camera behind him, the place's name on the banner, and the place is his checkpoint (a fall or a death brings him back there). He blinks untouchable
for 3 seconds, as after a respawn, so a Snuffer that notices him on arrival gets no free blow (nor one while the old place fades out). The vale's summit is sealed by a ward until the Dawn Gate opens, and the ward would
throw him out of the observatory and the Great Beacon's room again: a place inside it opens the Dawn Gate for him, and a hint says so (a place beyond Frostbloom Hollow's ice gate, the Hollow, or beyond Emberfall's ward of fire, the Furnace and the caldera, opens that gate the same way). `tools/travel-check.mjs` holds every place to a standard (headless: a floor under it, clear of
props, rock and colliders, out of the water and off a slope he would slide down, 6 m from the Snuffers and from a door that is awake, in no pocket, and in the walkable country with the realm's gate open); `tools/travel-test.mjs`
goes to every one of them through the real menu pages, then does it with the mouse and with taps on a phone held either way.

## The realm

Gloaming Vale is a valley that has been stuck in twilight ever since the Snuffers stole the sunrise. Elder Wick, the last
Lantern Keeper, asks you to relight the five Beacon Lanterns. Each one you ignite pushes the sky a step towards dawn —
the whole valley is lit twice (dusk and daybreak) and the world cross-fades between the two as you progress.

| # | Beacon | Where | What it asks of you |
| - | --- | --- | --- |
| I | Hearth | Hearth Village, spawn | Tutorial: jump, glide, fire. |
| II | Isle | Mirrormere lake | Run off the end of the dock and hop the three big lily-pad stones across to the shrine island. |
| III | Mill | Windmill hill (spiral road) | Light the three braziers to raise the portcullis. |
| IV | Sky | Floating isles | Bounce off the mesa mushroom, then glide island to island. |
| V | Dawn | Observatory at the top of the spiral mountain | The Dawn Gate only opens once four beacons burn; until then a shimmering violet ward wall seals the whole mountain. |

* **Snuffers** come in three kinds: plain ones (fire or charge), *bell* Snuffers (armoured — fire bounces off, charge them)
  and *thorn* Snuffers (spiked — don't ram them, burn them). Every one goes down in a single hit of the attack that works on it, as in the original.
* **Sparx** the dragonfly is your health bar, as in the original: he starts at full health, **gold**, and every hit that lands turns him down a colour, **gold → blue → green →
  gone**; with him gone the next hit is lights out. Bunnies you scorch or ram (and often a Snuffer you defeat) release a healing butterfly: a white 3D butterfly with a soft glow that
  flutters up and flies to Sparx, who eats it and gets one colour back (with him gone it flies to Spyro instead, and he pops back). **Every tenth bunny** (the 10th, 20th and 30th of the level's 37) leaves a
  rare **blue butterfly** instead, as in the original: bigger, deep blue and shining, with a sparkle trail and a chime, that brings Sparx **all the way back to gold** at once, from any colour and from gone;
  with him already full it waits a minute and a half (an ordinary one 25 s). A new life starts with gold Sparx again.
  He is a real 3D dragonfly (big goofy eyes, antennae, a swishing tail and four glassy wings, flapping as he hovers), not a flat sprite, and a small one: about half a metre long. While he is with you he grabs the gems that are near (a little flick towards each); **with him gone nothing pulls gems in: you have to touch them**.
* **Butterflies** are real 3D models too (`src/game/models/creatures/butterfly.js`): a slim banded body with clubbed antennae and, on each side, a pointed forewing and a rounder hindwing with a
  little tail. The wings are two-sided sheets, deep blue on top with a bright sheen and a dark rim of white spots, dusty pale blue underneath, so a butterfly flashes blue and dull as it beats; they beat in
  bursts with short glides between. A flock of 18 smaller ones in every shade of blue (azure, cyan, sky, violet) drifts about the dry meadows near you; the ordinary healing ones are white and the rare full-heal ones the deepest, brightest blue.
* **Gems** are worth 1 / 2 / 5 / 10 / 25 (red, green, blue, gold, purple): cut stones whose facets flash as they spin. Vases, chests, cracked walls and enemies drop
  them, plus hand-placed trails and a few well-hidden treasures. Total: **700**. While Sparx is with you (and only then), gems within a few metres are drawn in
  on a curved lob (up, then down into Spyro, like the original), and every pickup makes a chunky yellow gem count hop and float in the corner
  for a couple of seconds.
* Ending the level shows a results screen (three stars) and drops you back into free roam, with a portal open above the lantern (below).

### The portal home

The last beacon does two things: the sun comes up, and a **portal pops open on top of the lantern**: a swirl of violet light that blooms in the lantern room's dome, right above the Great Beacon, while the camera slips in
under it to watch. It hangs far out of any jump's reach, so the light carries you: a **ring of light on the lantern room's floor** marks where the beacon's beam comes down, and **a jump made inside the ring** lifts Spyro up the beam, spiralling round the
lantern, into the portal and out of the realm (the screen fades to white, the next world is built behind a loading bar, and he steps out of the Gloaming Vale door in Dawnhaven). The results screen mentions it, and a hint appears as you walk up to the ring.
(From outside the observatory's dome hides the portal; the beacon's golden beam rises through it all the same.) Going back through Dawnhaven's door finds the vale **restored**: the sun up, every lantern and brazier burning, the mill's portcullis and the Dawn Gate open, and the portal over the Great Beacon open from the start (no finale plays again).
The rest is as on the first visit, so the gems, vases, chests and Snuffers are there to be had again and the best gem count can be bettered (it is kept when you leave by the portal).

## The homeworld: Dawnhaven

In the series a *homeworld* is the hub that connects the levels (the *realms*): a place of its own with a portal to each realm, secrets to find, and someone to talk to. **Dawnhaven** is that for the Lantern Keepers, and it is built the way the PlayStation hubs were
(Artisans Home, Peace Keepers, Magic Crafters): not a plaza with five doors on spokes but **a country of connected parts** joined by long, winding roads: caves and a mountain with a way through it, villages on terraces, a lake with a pier, a canyon, and every door in a place
of its own, some of them well hidden. A sunlit valley (always daybreak) of 432 m by 432 m, with 700 gems of its own and five secrets. You arrive through the portal over the Great Beacon and come out of the Gloaming Vale door in the first part; the others you have to find.

| Where | What it is |
| --- | --- |
| **The Landing Cove** | A lawn walled in by cliffs, with a fountain, a market, a hamlet, an enormous old tree and the **Gloaming Vale door** in a niche of its west wall. **Elder Wick**, who came ahead to look after the place, waits on the lawn and talks (it follows your progress: the realms restored, a hint towards a secret you have not found, how many you have). A signpost where the cove's road leaves. |
| **The Heartlands** | A meadow of two levels with a standing-stone ring, a ruined arch and a farm, crossed by the cobbled trunk road (130 m of it climbing to the Crag); roads branch off west (the terraces) and east (the lake). |
| **The Hearth Terraces** | A hillside village: a road that climbs west and north in long switchbacks (about 250 m of it), a yard at every turn with a fountain square, houses, wells and gardens, up to the **windmill** on the ridge. **Secret:** the wooden stair up the mill leads to a lookout with a chest and a purple gem. |
| **The hidden garden** | Off the terraces, a round glade ringed by 16 m of rock and open only along a narrow strip closed by a **cracked wall**. **Secret:** ram the wall (hold RAM and run at it); the garden has a chest, flowers and a purple gem. |
| **Mirror Lake** | A lake with a waterfall, reeds and lily pads, boats at the foot of **a 41 m pier** that runs out over the water to the **Tideglass Reach door**, standing on its own dais at the end of it. **Secret:** stepping stones lead west from the pier to a little islet and its chest. |
| **The Ember Canyon** | A red-walled canyon that winds north from the lake's far shore (about 300 m of road, braziers every 24 m, rock arches across it) to the **forge**: a smithy with a glowing furnace, a smoking chimney and an anvil, and the **Emberfall Crags door** in the cliff behind its court (awake: a swirl of ember orange). |
| **The Crag** | A mountain in the middle of the country with **a way through it**, a hundred metres of tunnels and halls inside and a road round it outside. The **south mouth** (a lane in front of a cliff, torches and banners at its foot) leads down a tunnel lit by torches and crystals to the **Echo Hall**: a round room with a skylight whose beam of daylight falls on a ring of runed standing stones. From the hall: the **winding way** goes down (70 m, turning three times) to the **Frost Grotto**, a dome of ice and glowing crystals with the **Frostbloom Hollow door** at its far end; a passage north leads on out to the Ascent; a passage east comes out on the road to the canyon; and in the hall's north wall a **cracked wall** shuts the **crystal vault**. **Secret:** ram the wall; the vault has a chest and a purple gem. |
| **The ledge road** | A cobbled road that begins under a rock arch on the Crag's west side and **winds once and a bit round the mountain, climbing 26 m over 238 m**, past lamps, benches and viewpoints, to the **summit** and the **Skyweaver Spires door** (awake: a rose swirl). **Secret:** the chest on the summit, with a view of the whole country. |
| **The Ascent** | North of the Crag, a road that climbs in a long curve to the **Guardian's Gate**: two colossal runed pillars and a violet field between buttresses of rock, closing the gorge. It is sealed for now (the Elder says it will open when the lanterns of every realm burn, and one of the five realms still sleeps): the teaser for a guardian to come. |
| **Five doors** | Each a stone arch with a banner on each pillar, a rune plate and torches, each in a different kind of place: a cove, **inside a mountain**, **out on a lake**, in a **canyon's head**, **on a summit**; and at very different walks from where you arrive (the first door 11 m away, then 210 m, 300 m, 370 m and 390 m of walking). **Gloaming Vale**'s, **Frostbloom Hollow**'s, **Emberfall Crags**' and **Skyweaver Spires**' are awake (a swirl of violet light, an icy one for the second, an orange one for the third, a rose one for the fourth; each turns **gold** once you have restored its realm: a lantern lights on the HUD for each one). The last, **Tideglass Reach**, still sleeps: a slab of stone and a dim swirl, and what it is called when you come near. Walking into an awake door's light changes the world. |

What the hero keeps between worlds is saved in the browser (`localStorage`, key `gloaming-vale/progress/v1`: which realms are restored with their best gem counts, and which of the five secrets were found; where storage is unavailable the game plays the same and forgets).
The title menu offers **VISIT DAWNHAVEN** once a realm is restored, and `?world=home` opens the page in Dawnhaven (and `?skip=1` skips the title in the realm as before).

### How the Crag's caves are made

A heightfield cannot have a cave, an arch or an overhang, so the Crag is not part of the terrain: it is a **rock mass** (`src/game/massif.js`), one function of (x, y, z) that is negative inside the rock: a few overlapping mounds for the mountain, from which are cut tunnels (an arched section along a polyline), domed halls, a skylight shaft and a notch for the ledge road (and under that road a retaining wall is left), all joined with smooth maxima so that the junctions are rounded, and a little 3D value noise on top. The terrain draws the cave floors
(under the mountain it is level, following the tunnels' floors: `home/crag.js`), the rock is meshed by **surface nets** over a 1.5 m grid with the vertices drawn onto the exact surface, and the same function is the collision: the hero is pushed out of the rock by a ring of samples round his body, stands on the rock's own ground (the ledge road, the summit), and the camera is held back by it and comes closer inside a cave.
The light inside is worked out per vertex like the rest of the world's baked light: how much sky a point sees (nine rays through the field), the corner shadows, the sun where a mouth or the skylight lets it in, and the glow of the crystals and torches placed in the caves, so the walls near a torch are warm and the hall under its skylight has a beam of daylight; at a mouth it fades into the outdoor light.
The borders between the rock's textures (cobble on the ledge road, grass on the gentle ground, cliff for the rest) are **cut, not chosen**: a texture chosen for a whole triangle draws a staircase of teeth, so each texture has a score read at the vertices and every triangle the zero line crosses is cut along it, which makes the borders smooth lines. The mountains of the heightfield between the parts get the same treatment where rock meets grass (the border follows the contour of the steep slope, `cutByContour` in `terrain-mesh.js`).
Gloaming Vale has no rock mass, names no steep slope, and its world is byte-for-byte what it was (its terrain mesh has the hash it had).

## The second realm: Frostbloom Hollow

The door in Dawnhaven's Frost Grotto that slept now opens on **Frostbloom Hollow**, the first realm made with the foundry (described below). *An endless winter has frozen the blossoms of the Hollow asleep.* Five **Frostblooms** — flowers of ice
with a flame inside, a new model — must be thawed by fire. Each one that blooms moves the realm a step from its **frozen night under the aurora** (ice teal and snow white, a cold moon, a green glow in the north) towards a **blossom dawn** (a low rose-gold sun,
pink-lit snow, a cornflower sky): the same two lit states as the vale's dusk and daybreak, in other colours. The **ice gate** across the gorge to the Hollow melts when four have bloomed, and the **Heartbloom** in the Hollow brings back the spring:
a ring of light opens over it and carries the hero home. A country of 408 m by 408 m, 650 gems, three secrets, 24 Snuffers (8 plain, 9 in bells, 7 with spikes), and a journey to each Frostbloom of a different length (31, 120, 201, 283 and 413 m of walking).

## The fourth realm: Skyweaver Spires

The summit of the Crag, at the end of the ledge road, has a door that wakes: **Skyweaver Spires**, the third realm made with the foundry and the first that is not a country at all but **islands in a sea of cloud**. *The Skyweavers wove the winds into the spires of the sky and kept them there with five great Windbells; when the bells fell silent the winds fell slack, and the clouds have lain still ever since.* Five **Windbells** — a bell of bronze in a frame of two marble pillars, silent and dull blue-grey until fire is breathed at it, then gold, swinging, with a heart of light in it and a ring of runes turning on its plinth, and a bell's ring, a new model and a new sound — are rung with fire. The last, the **Loom Bell** at the top of the world, opens the ring of light that carries the hero home. A country of 480 m by 480 m with ten islands, 550 gems, three secrets, 14 Snuffers (3 plain, 6 in bells, 5 with spikes), and a journey to each bell of a different kind and length: 24 m of walking, **a row of slabs** (128 m), **a glide of 41 m** with no way on foot (181 m), **a whirlwind and the spires** (523 m) and the Loom (619 m).

## The realm foundry: how the next realms get made

After Dawnhaven the question was how to make more worlds like it without starting from nothing each time, so what had been learnt was written down as a **kit**, a **generator**, a **checker** and a **skill** (`.claude/skills/new-realm/`, where a person or an AI assistant is
told how to work: the workflow, the principles, the engine's contract, the recipe, the gates and the pitfalls). The principles come from looking at what made the PlayStation games' homeworlds and levels good: a place is **a country of parts** with a character each, joined by roads long enough to be a journey; it has **levels**
(a way down under a mountain, a way up its flank) and height as the reward; its goals stand in **different kinds of place** (a landing, a clearing, an island, a summit, a cave, a glide, a puzzle, a crater) and at very different walks; its secrets are **off the path** and ask something of the hero; the danger **grows** with the
journey; a trail of gems **leads the way**; and a place has **a theme of two or three colours**, not a handful.

* **The kit** (`src/game/realm/`): the ground made of ribbons of open ground between mountains (`country.js`, with the landforms a realm wants: a lake's bowl, a mound, a shelf, a glade walled in by rock, a ravine), the level descriptor made from a **brief** (`level.js`), the brief itself, which is a design written down as data and **refused** by `defineBrief` when it is not one (too few parts, goals alike, no secrets, a goal's colours in the wrong shape...) (`brief.js`), the stages of a level script and the three every realm has (its goals, the ring of light, the treasure) (`populate.js`), the situations a goal can stand in and how each is checked (`situations.js`), the placement helpers (`helpers.js`), and caves from data (`rockmass.js`).
* **The generator** (`node tools/new-realm.mjs <id> --name ... --tagline ... [--door <id> --wake-door]`): copies the starter, a small complete realm that passes every rule, renames it all through, gives it a noise seed of its own, registers it (and its TRAVEL places, found and validated, and, with `--wake-door`, the door of Dawnhaven that leads to it) and runs the checker.
* **The checker** (`node tools/realm-check.mjs <id>`): 41 rules, none of them a vague one. **Hard:** the build is deterministic (a level script runs twice, dry and wet), the hero starts on firm level ground in the open, every goal can be reached (on foot, by a jump, through a broken wall, through an open gate; a glide goal by gliding), the ring of light has a level floor, the treasure adds up to a round number and is placed where it can be collected, no prop stands in a road, no road is steeper than the game draws one, every banner it puts up fits the screen, its HUD icons and every texture it uses exist. **Design:** the situations of the goals are what the brief says (an island has water all round it, a cave a roof over it, a crater a rim), they differ, the walks to them differ, the country has levels and height worth the climb, every part can be walked along, the roads make a loop and none runs out into nothing, the secrets are off the road and one is behind a wall, danger grows by thirds of the way, the gem trail leads along the roads, and the ground is made of few textures. A rule that a realm cannot yet meet is a **waiver** written in its brief with a reason: a to-do the checker prints on every run until it is deleted. The two worlds that came before the rules are held to them with their departures written down (`tools/lib/realm-rules.mjs`).
* **The rest:** a map of any world (`realm-map.mjs`), the TRAVEL places (`realm-travel.mjs`), the realm played end to end in the real game (`realm-test.mjs`), the whole foundry tested (`foundry-test.mjs`: it generates a scratch realm, checks it, finds its places, plays it in a scratch dev server, and checks that the generator refuses what it should), and the pins that keep the old worlds from changing by accident (`world-hash.mjs`).

Frostbloom Hollow took the foundry from a design to a playable realm; what it needed that the foundry did not have became part of it (own textures for roads, lake and far mountains, the props' skin, caves from data, a cave goal under a skylight, places beyond a gate, a recoloured gate, a validated goal look).

Emberfall Crags was the second made with it, in one pass, and what it needed that the foundry did not have became part of the kit in turn: a **liquid** that is not water (`level.liquid`: the lake is drawn lit from within with a texture of its own, splashes sparks, and burns from a depth the realm says), **mountains that stay walls** (`mountain.margin`: a mountain stays well above the ribbon floor beside it, or a hero walks up its slope), a glide goal that must also have **a way off** again (the situation check looks for a ledge in reach on the other side, so a hero is never stranded on the stack), the sky's **clouds and distant ridges** in a realm's own colours, the dusk's **embers**,
a gate that is a ward of fire, and a realm walker that can **glide** (`tools/realm-bot.mjs` plans the legs with `tools/lib/glide.mjs`).

Skyweaver Spires was the third, and it asked for a country that is not ground: a **sea** (`brief.sea`, `rockLine`), **whirlwinds** (`realm/whirl.js`), a goal that is a **lift**, the **air journey** (`brief.air`, `tools/lib/air.mjs`: links as data, held to the numbers, a walker that rides them, TRAVEL places on islands that cannot be walked to), the walk map's hops for **slabs** that hang in the air, and a goal's own ignition sound. The skill's table of realms still to make now lists one.

## The hero

Spyro is built in code like everything else (`src/game/models/creatures/spyro.js`): about 2 k vertex-coloured, Gouraud-lit
triangles on a pivot rig (no skinning). The proportions follow the classic PS1 character sheet: a boxy head with a broad flat muzzle
and large glossy eyes on the forehead wall, two thick ringed horns swept back and a flat orange crest fin behind the crown, a tall
upright chest with banded orange plates from the throat down to the belly, four short columnar legs with flat three-toed feet,
wings held up like triangular sails (dark red membrane, broad orange leading edge; they roll out flat for the glide) and a long tail
that tapers to a ringed orange tip. It is modelled by hand as original geometry, measured off orthographic views of the character
(every size is authored in "sheet units" and converted with one scale constant): no ripped model, texture or animation data is used.

**The ram.** When he charges, the head tucks steeply down (its front 65 to 70° below level, chin toward the chest; it used to dip about 34°) and the horns bend forward along their
length until they point ahead like a bull's, tips level, instead of standing straight up; the crest fin and the wings stay up behind. The horns are a mesh of their own that is bent in place
while the charge comes and goes (a smooth bend along the tube, not a swing of the whole horn), and every other pose keeps them exactly as they were. The same goes for a ram jump.

## How the PS1 look is made

| Hardware trait | How it is reproduced here |
| --- | --- |
| 320×240 frame buffer | Scene renders into a 320×240 target (optional wide / 480-line modes), integer-scaled or "sharp bilinear" to the window. The HUD is drawn at that same internal resolution. |
| Integer vertex coordinates ("jitter") | Clip-space vertices are snapped to whole pixels in the vertex shader (`ps1Snap`). |
| No perspective correction | UVs are interpolated affinely (`uv * w` trick), so big near polygons swim exactly like the original. Toggle in options. |
| Gouraud shading only | All lighting is baked into vertex colours. Static geometry stores irradiance for **both** moonlit-gloaming and daybreak (heightfield shadow ray-march + prop shadow stamps) and the shader blends them by the current time of day. Dynamic models use one directional + ambient term evaluated per vertex. |
| `texture × colour × 2` blending | 0.5 vertex colour is neutral, values above brighten — the GPU's modulate mode. |
| Per-vertex fog | Fog is computed in the vertex shader and interpolated, so it bands across large triangles. |
| 15-bit colour + ordered dither | Final pass quantises to 5 bits per channel after adding the PS1 4×4 dither matrix (offsets −4…+3). |
| Nearest filtering, no mipmaps | Textures are tiny (16–64 px), palette-limited, point sampled. |
| 1-bit / 50 % / additive transparency | Cut-outs are alpha-tested; water and glass use the 50 % blend; glows are additive. |
| 30 fps | Optional lock: simulation keeps running while every second frame is presented. |

Honest caveat: the *rendering artefacts* are faithful, the *budgets* are not — the terrain is a ~52 k-triangle heightfield,
far more than a PS1 could push. A frame submits roughly 200 k triangles and 250–300 draw calls (the static world meshes are
not frustum-culled), which integrated graphics and recent phones handle at 320×240; **Options → Graphics → 30 FPS lock** helps older devices.

```
  roads.js drape.js  the cobble and dirt roads, draped exactly on the terrain mesh (cut against its triangles, so they never hover or sink) and merged where they meet (one texture, one worn-edge shading)
  river.js water.js  the river's drawn surface (it meets the lake without a step) and its water, cut to the banks so it stops exactly at the waterline
  props/  models/    procedural scenery, architecture, hero, creatures and interactive objects
  levelgen/          deterministic placement of props, enemies, gems, hints (islands.js plans the floating isles' decor clear of what stands on them)
  player.js camera.js collision.js   kinematic controller, chase camera, heightfield + collider world
  gemcounter.js      the floating, bouncing 3D gem count: extruded numerals drawn as a second little scene over the world
  systems/           gems, Sparx, beacons, enemies, critters, NPC, objects, ambience, portals (the doors and the ring above the Great Beacon: pop-up, trigger, the ride up the beam)
  app.js hud.js menu.js cinematics.js   title → intro → play → finale → results, HUD, menus (finger-sized rows on touch), options, the travel menu's pages and warp
  travel.js          the places of the TRAVEL menu (85, in the five worlds): name, spot, facing, floor, `opens` for a place beyond a realm's gate
  debug.js debuginfo.js   debug mode: the readout / crosshair / collider wireframes, and the pure functions behind the readout
tools/               QA + dev tooling (see below)
.claude/skills/new-realm   the realm foundry as a project skill: the workflow, the principles of the PlayStation worlds it is built on, the engine's contract, the recipe, the gates, the pitfalls
docs/index.html      the built single-file game
```

The bot scripts need the dev server (`GV_HMR=0 npm run dev`) and Playwright with Chromium.

Dev-only scenes (not in the single-file build) are reachable through `?test=`: `props` (scenery gallery), `models`
(hero, enemies and objects with their test poses), `world` (the realm with a scripted camera), `pipeline-test` (every PS1
effect on a test scene) and `play` (bare world plus controller, for tuning movement). Example: `http://127.0.0.1:5173/?test=models&only=spyro&pose=run`.
